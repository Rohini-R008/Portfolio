Things I have built

Secure IoT Monitoring Platform

A security-first platform for monitoring IoT sensor fleets. Every device has its own X.509 identity, all traffic runs over mutual TLS, access is role-controlled, and credentials can be revoked live. It ships with a deliberately insecure twin and an automated attack runner that proves each defense — the same attack succeeds on the insecure stack and is blocked on the secure one. Sustained ~1,700 msg/s with 100% of unauthorized messages blocked in testing.

DevAgent — autonomous PR reviewer

An AI developer agent that reviews GitHub pull requests through a LangGraph + LLM pipeline triggered by webhooks, and diagnoses GPU-memory issues in PyTorch/CUDA code using static analysis plus RAG retrieval over the codebase. Everything it does is visible in a Next.js dashboard.

Cloud-Deployed Data Pipeline

A production-style pipeline that ingests messy, mismatched CSV sources, validates every row with Pydantic, loads clean data into cloud Postgres, and quarantines bad rows instead of silently dropping them. It runs unattended on a daily GitHub Actions schedule and serves the data through a live FastAPI API.

Distributed Rate Limiter

A rate-limiting and API abuse-detection gateway in Spring Boot, backed by Redis with atomic Lua scripts and Postgres. I tracked down and fixed a time-of-check-to-time-of-use concurrency race with a compare-and-swap loop, implemented both token-bucket and sliding-window strategies, scaled it from a single node to multiple instances, and load-tested it with k6.

About

I'm a software engineering student in Bengaluru, drawn to backend and distributed systems — the parts of software that have to stay correct under load, under attack, and when the input is messy.

My projects share a theme: reliability you can verify rather than just claim. I've built a security-first IoT platform that proves each defense by running the same attack against a secure and an insecure stack, a rate limiter I hardened against a concurrency race and load-tested from one node to many, and a data pipeline that quarantines bad rows instead of dropping them. I like measuring what a system actually does.

I work mainly in Python, Java, and TypeScript, and I enjoy the whole path from an API and its database down to the Docker and CI that ship it. Right now I'm going deeper on distributed systems and AI-powered developer tooling.
